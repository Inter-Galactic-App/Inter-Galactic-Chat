# Beta Bug Report Template

Use this when a beta user reports something broken, confusing, or unreliable.
Keep reports short enough that users will actually finish them, but complete
enough that the team can reproduce the issue without a long back-and-forth.

**Severity:**
- `critical` - Data loss, security/privacy risk, login blocked, app crash loop,
  messaging fully unusable, or beta rollout must stop.
- `major` - Important feature is broken or very unreliable, but users have a
  workaround or only a subset of users is blocked.
- `moderate` - Noticeable bug that affects normal use but does not block the
  main workflow.
- `cosmetic` - Visual polish, wording, alignment, animation, or other minor UX
  issue that does not change functionality.

## Evidence

Attach whatever is available. Do not block intake if one item is missing.

- Logs: include app diagnostic logs or relevant system/browser logs.
- Screenshots or screen recording: blur private room names, messages, and
  account details when possible.
- Platform/version: include OS version, browser version, device model, and app
  build number.
- Reproduction context: room type, call type, encrypted vs unencrypted room,
  network conditions, and whether restart/logout changes the behavior.
