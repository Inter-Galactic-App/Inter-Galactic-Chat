# Quarantine Preparation: Inactive Groundwork

This release includes standalone policy, clock, record and inventory models,
plus disconnected notice and recovery-panel components and their tests.
These components are not mounted or called by production startup or settings.
No native bridge, database admission wrapper or cleanup coordinator is included.

Automatic qualification, enrollment and removal remain disabled. The pure
models' trust inputs and cleanup verdicts are not filesystem capabilities or
proof that an account, writer or native resource is safe. Presentation callbacks
can execute if a future caller mounts the widgets; wiring them requires a
separate reviewed implementation. No retention countdown or deletion guarantee
is exposed by this groundwork.

Production completion is deferred. Safe continuation needs complete SDK effect
exclusion, actual opened-file association and native resource settlement, not
getter-only fencing or a successful logical database close. Existing uncertain
copies may remain beyond intended expiry. No live-data or deletion authority
follows from the tests or this source preparation.

Activation requires separately reviewed native storage, bridge, admission and
runtime integrations with exact account/file association, writer exclusion and
resource-settlement evidence. Reassess the whole dependency and runtime scope
before implementing or connecting those integrations.
