### The IPA is the artefact of record, not the xcarchive

Worth writing down because the obvious source is the misleading one. The
xcarchive `Info.plist` records

    SigningIdentity = Apple Development: NICHOLAS JOHN TOWLE (N3Z8YQC7MJ)

because that is what signed the **archive**. The export re-signs. Reading the
exported bundle instead — `codesign -dv` on `Payload/Runner.app` — gives
`Apple Distribution … (8RSRT93XU9)` with a Team Store profile.

Trusting the archive plist would have rejected a correct distribution build as
development-signed. 0.8.0+993 has the identical shape, so this is how this
project's Apple exports look, not an anomaly of this one.

### The retention path is not the evidence

`iOS_Builds/` is gitignored (`.gitignore:51`), like `Desktop_Builds/` and
`Android_Builds/`, so it is **non-durable by workspace policy**. The path
`iOS_Builds/Inter-Galactic/0.8.1+1003/InterGalactic.ipa` is a locator. The
evidence is the container digest above plus the 26 payload digests below, which
survive that directory being swept.

## Digests were verified, not accepted

IOS supplied a 26-line digest manifest with the build. REVIEW re-hashed all 26
from the extracted bundle independently:

- 316 files walked, 26 Mach-O identified by magic;
- path sets agree exactly — nothing only-mine, nothing only-theirs;
- **all 26 digests match**, and the container digest matches;
- control: one expectation deliberately corrupted was reported as a
  disagreement, so the comparison is known to be capable of failing.

The `pwsh-preview` gate agrees separately: `26 native file(s) mapped to licence
records`, 55 `[ok]` lines, 0 failures, and the three `staticLimbs` on `Runner`
each resolve to a licence record.

## The 26th binary: `InterGalactic Share Extension.appex`

New since 0.8.0+993, and the reason this was a re-sweep rather than a digest
update. `tools/release/remeasure_apple_payloads.py` **refused to write any
digest** while the path set differed:

```
COMPOSITION CHANGED - refusing to touch any digest.
  + PlugIns/InterGalactic Share Extension.appex/InterGalactic Share Extension
    (never enumerated, never swept)
```

That refusal is the point. Digests moving with the path set identical is a
rebuild; the path set moving means a binary nobody has opened, and editing
digests past it produces a mapping that *looks* complete over an unexamined
component.

### What it contains

First-party project code, and every check says so:

- **Its own symbols.** 12 defined, of which the only non-metadata entry is
  `_TtC29InterGalactic_Share_Extension19ShareViewController` — Swift mangling
  for module `InterGalactic_Share_Extension`, class `ShareViewController`. Every
  other class it names is Apple's: `UIViewController`, `NSItemProvider`,
  `NSExtensionItem`, `INSendMessageIntent`, `UILabel` and so on.
- **Its linkage.** `otool -L` lists only system frameworks and the Swift
  runtime. No `@rpath` framework, no third-party dylib, nothing statically
  merged.
- **Its strings.** `vodozemac`, `curve25519`, `sqlite`, `openssl`, `SDWebImage`
  and `kiss_fft` each return **0**, against a control of `Share` ×24 proving the
  search works. No version banner, no configure line, no third-party copyright.
- It uses the App Group `group.chat.intergalactic.app`, consistent with the
  Broadcast Extension.

Mapped to `project_license`, alongside `App.framework`, `Runner` and the
Broadcast Extension.

## Nothing else moved

The full 51-family symbol sweep was re-run across all 26 binaries, not only the
new one, with the same controls in both directions. The result is
**shape-identical to 0.8.0+993**: every known component resolves as *defined* in
its own framework, the nonsense probe returns 0, and 30-plus probes for
components this bundle does not carry return 0.

### The Rust roster is unchanged, which is what keeps the shipped notice valid

`assets/licenses/rust-crates-NOTICE.txt` names 59 crates plus the Rust standard
library at specific versions. A toolchain change would have staled it silently,
so it was re-measured from this binary rather than assumed:

| | 0.8.0+993 | 0.8.1+1003 |
|---|---|---|
| rustc commit embedded in `Runner` | `e408947bf…3bd1` | **identical** |
| `registry/src/…` crate-versions | 43 | **43, same set** |
| `/rust/deps/…` std-vendored | 7 | **7, same set** |

Zero added, zero removed. Controls: the `vodozemac-0.9.0` path is findable in
the new binary, a nonsense crate path is not. The notice as shipped describes
this artefact.

## What this does not establish

- Sufficiency is not ruled on. This records what ships and what it is.
- A symbol sweep proves presence, never absence in general — only absence of
  the families probed. The probe list is written out in `0.8.0+993-sweep.md`
  rather than summarised as "clean".
- Apple re-signs on distribution, so a binary a store user receives is not
  byte-identical to the one here. These digests pin **the artefact this project
  submitted**, which is the thing this project controls.
- The notification service extension is still not in this build. If it ships,
  there will be a 27th Mach-O that has never been swept.
